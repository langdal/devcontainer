generic-devcontainer · architecture

Three files, one guarded sandbox

The whole tool is a host-side script, a Dockerfile, and an entrypoint — wired together so an AI agent can code inside a real container but cannot reach the network except through a filtered gate. Here is how a run flows from your terminal to a locked-down shell.

01

On the host — orchestration & build

Your machine· runs as you no container yet

./dev — the lifecycle wrapper

Bash script you invoke from any project. It owns everything outside the container.

  • Bakes your UID/GID into the image; auto-builds & rebuilds
  • Reuses / restarts the dev-<dir> container, else creates one
  • Mounts volumes, forwards ports, passes GITHUB_TOKEN & git identity
  • Merges allowlists; selects the mode (normal / maint / dind)

Dockerfile — the image recipe

Built once into the base image everything runs from.

  • Installs mise + base tools into /mise
  • Bakes in allowlist.base & firewall scripts
  • Stages entrypoint.sh and the .zshrc skel
Dockerfile → build → image
./dev → docker run (drops into the container)
02

Inside the container — boot sequence & the boundary

Container boundary user: vscode · no sudo

entrypoint.sh — runs as root on every start, then drops privileges

1
Raise the firewall firewall-init.sh
iptables OUTPUT → DROP, tinyproxy up, exports HTTPS_PROXY. Fails closed — no firewall, no start.
2
Install project tools mise install
Seeds rc files, ensures mise activate, installs from /workspace/mise.toml.
3
Configure git
Marks /workspace safe; seeds identity from host only if unset.
4
Drop to vscode exec gosu vscode
Everything you run happens here — unprivileged, behind the wall.

Your live code, edited in place.

The security boundary — the only way out is the gate

Allowed egress via proxy

Requests to allowlisted hosts flow out through tinyproxy — the one user permitted to reach :80 / :443.

Dropped kernel

Any raw socket or off-allowlist host from vscode is dropped by the iptables owner rule. No exfiltration.

03

Same wiring, three modes

./dev
Normal. Firewall on, no sudo. The everyday hardened shell.
./dev --maintenance
Separate container, firewall off, sudo back on — for installing system packages.
./dev --dind
Adds rootless dockerd; nested pulls still routed through the proxy.
